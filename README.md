# Информационная система учета заявок на подключение услуг интернет-провайдера

Курсовая работа: веб-приложение для учета заявок провайдера с ИИ-ассистентом.

## Описание

Система позволяет:
- Управлять услугами провайдера (CRUD операции)
- Управлять заявками на подключение (CRUD операции)
- Связывать заявки с услугами (многие-ко-многим)
- Отслеживать статусы заявок (новая, в работе, выполнена)
- Использовать ИИ-ассистента для консультаций и создания заявок

## Технологии

- **Python 3** - язык программирования
- **Flask** - веб-фреймворк
- **SQLite** - база данных
- **SQLAlchemy** - ORM для работы с БД
- **HTML/CSS** - интерфейс пользователя

## Установка и запуск

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Запуск приложения

```bash
python app.py
```

Приложение будет доступно по адресу: `http://localhost:5000`

### 3. Первый запуск

При первом запуске автоматически создается база данных `provider.db` с тестовыми данными:
- 4 услуги (Базовый интернет, Стандартный интернет, Премиум интернет, Интернет + ТВ)
- 2 тестовых пользователя:
  - Администратор: логин `admin`, пароль `admin`
  - Пользователь: логин `user`, пароль `user`

**Важно:** При первом запуске необходимо войти в систему. Неавторизованные пользователи будут перенаправлены на страницу входа.

## Авторизация и уровни доступа

Система поддерживает два уровня доступа:

### Администратор (admin)
- Полный доступ ко всем функциям
- Управление услугами (CRUD)
- Управление заявками (CRUD)
- Доступ к ИИ-ассистенту

### Пользователь (user)
- Просмотр списка услуг (только чтение)
- Доступ к ИИ-ассистенту для создания заявок
- Регистрация новых аккаунтов

**Тестовые аккаунты:**
- Администратор: логин `admin`, пароль `admin`
- Пользователь: логин `user`, пароль `user`

## Функционал

### Управление услугами

- Просмотр списка услуг (все авторизованные пользователи)
- Добавление новой услуги (только администратор)
- Редактирование услуги (только администратор)
- Удаление услуги (только администратор)

### Управление заявками

- Просмотр списка заявок (только администратор)
- Создание новой заявки через форму (только администратор)
- Создание заявки через ИИ-ассистента (все авторизованные пользователи)
- Редактирование заявки (включая изменение статуса) (только администратор)
- Удаление заявки (только администратор)
- Связывание заявки с одной или несколькими услугами

### ИИ-ассистент

ИИ-ассистент помогает:
- Консультировать по услугам провайдера
- Пошагово создавать заявку на подключение

**Доступ:** все авторизованные пользователи

**Примеры диалогов:**

1. **Консультация:**
   - Пользователь: "Какие услуги доступны?"
   - Ассистент: Показывает список всех услуг с описанием и ценами

2. **Создание заявки:**
   - Пользователь: "Оформить заявку"
   - Ассистент: Пошагово собирает данные (имя, телефон, адрес, выбор услуг)
   - После подтверждения создается заявка в системе

## Модели данных

### User (Пользователь)
- `id` - уникальный идентификатор
- `username` - имя пользователя (уникальное)
- `password_hash` - хэш пароля
- `role` - роль (admin или user)
- `created_at` - дата создания

### Service (Услуга)
- `id` - уникальный идентификатор
- `name` - название услуги
- `description` - описание
- `price` - цена (руб./мес.)
- `speed` - скорость интернета
- `created_at` - дата создания

### Application (Заявка)
- `id` - уникальный идентификатор
- `client_name` - имя клиента
- `client_phone` - телефон клиента
- `client_address` - адрес подключения
- `status` - статус (новая, в работе, выполнена)
- `notes` - дополнительные заметки
- `created_at` - дата создания
- `updated_at` - дата обновления
- `services` - связь многие-ко-многим с услугами

## Архитектура

Проект использует простую MVC-подобную архитектуру:
- **Models** (`models.py`) - модели данных
- **Views** (`templates/`) - представления (HTML шаблоны)
- **Controllers** (`app.py`) - контроллеры (маршруты и логика)

ИИ-ассистент реализован как отдельный модуль (`ai_assistant.py`), который можно заменить на реальный API (например, OpenAI) в будущем.

## Примечания

- ИИ-ассистент использует предопределенные ответы на основе ключевых слов (имитация ИИ)
- База данных SQLite создается автоматически при первом запуске
- Все данные хранятся локально в файле `provider.db`
- При первом запуске автоматически создаются тестовые аккаунты (admin/admin и user/user)
- Пароли хранятся в виде хэшей (Werkzeug security)
- Для добавления новых администраторов необходимо изменить роль пользователя в базе данных или добавить через Python shell
